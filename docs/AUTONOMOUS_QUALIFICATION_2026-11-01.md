# Expanded isolated qualification — 2026-11-01

This follow-up covers complete VM state, versioned Windows deployment, public provisioning, failure handling and additional operating-system/load checks. It builds on the [earlier Windows qualification](WINDOWS_LAB_QUALIFICATION_2026-11-01.md) and [operational guide](HARDENING_AND_QUALIFICATION.md). All accounts, signing identities, data and network endpoints used here belong to disposable laboratory fixtures. No client environment, proprietary VPN key container or production signing key was used. Hosted Actions and workflow configuration were unchanged.

## Code and behavior

- Offline state bundles capture a flattened disk, UEFI variables and optional software TPM state. They verify firmware compatibility and every resource before replacement, reject backing-chain changes during flattening, serialize lifecycle operations and persist restore intent. Recovery after a real process exit between resource renames restores the previous complete generation. Profiles pin an immutable complete base and receive independent writable state and runtime endpoints.
- Windows installation verifies a complete signed generation before publishing `installation.json`. Existing concrete paths retain their generation; activation requires explicit configuration/pin updates and startup. Rollback validates its destination, including when the selected generation is damaged. Staging interruption, publication sharing failure, deployment exclusion and tampering preserve the selected version. Private DACL installation works without SACL privileges.
- Provisioning stages a SYSTEM SetupComplete hook during specialize and installs drivers/QGA after Windows Setup, without autologon. A different existing hook is rejected; OEM-key restrictions outside Enterprise/Server remain documented. A short specialize command fits the documented [259-character RunSynchronousCommand limit](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-deployment-runsynchronous-runsynchronouscommand-path). Optical seed media avoids VVFAT/competing answer-file behavior; the installed disk precedes installation media on reboot. Live-VM checks precede disk/seed mutation. Detached installation has private runtime paths and retains ambiguous process ownership rather than terminating an unidentified process.
- A POSIX direct controller uses native key-authenticated SSH and passes large scripts through stdin. It preserves payload EOF, rejects unsupported password fallbacks and checks source identity during streaming. Structured rooted file/sync operations require their documented remote runtime. This does not qualify every minimal or Python-free target image.
- Windows control connections use native local Winsock sockets with filesystem DACLs. There is no TCP control fallback. A FIFO gate prevents local Windows audit writers from starving one another before interprocess byte-range locking.
- Lost QGA acknowledgements, worker interruption, corrupt replies and corrupt native stdout retain indeterminate transaction identities and reject replay. Storage reservation failure prevents dispatch; failure to persist a post-dispatch result preserves the reserved identity for reconciliation.
- The worker owns resident runspace slots, pipeline buffers, streams and native process pipes explicitly. Windows PowerShell/.NET Framework additionally retains internal asynchronous Event handles until finalization: a component experiment increased from 568 to 636 handles across 200 native jobs and fell to 593 after finalizers ran. Periodic collection after 32 native completions bounds this framework backlog, without waiting on the finalizer thread. The same fixture with periodic collection remained around 601–609 handles after initialization. Resource thresholds and the soak's 120-second warm-up were not relaxed.

## Remaining external boundaries

These finite tests establish the recorded laboratory behaviors, not universal correctness or indefinite leak freedom. Native x64/WHPX/KVM acceleration, physical TPM/EK/PCR7 attestation and hardware timing remain separate acceptance work. The Windows ARM QEMU port used for the Windows-as-Host check was software emulation; its vendor signing status is not production trust evidence. Managed software TPM launch/quiescence currently requires a POSIX Host.

Lab Authenticode/AllSigned and tamper tests use a private nonexportable test certificate. Production CA/EV trust, timestamping, revocation/enterprise execution policies and release distribution remain outside them. Proprietary provider installation, licensed version-specific CLI recipes, driver interoperability and actual client routing require separately approved media and a dedicated provider test environment. No such acceptance is inferred from a custom-provider fixture or from creating a VM.
