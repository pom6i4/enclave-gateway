# Сохранение доказательств при блокировке средства защиты

[English](../ENDPOINT-INCIDENT.md) · [Русский](ENDPOINT-INCIDENT.md)

Если средство защиты обнаружило или заблокировало процесс `egw`, прекратите
отправку запросов через этот маршрут и действуйте по процедуре ИБ. Один лишь
таймаут не доказывает вмешательство антивируса, а действительная подпись не
подтверждает совместимость с ним. Экспериментальный foreground-профиль
[не прошёл стендовую приёмку KES](../ENDPOINT-POLICY.md#qualification-status).

## Действия после обнаружения

1. Сохраните запись транзакции на Host и журнал воркера. Не повторяйте команду
   с новым идентификатором ради успешного ответа.
2. Сверьте неопределённый исход с фактическим состоянием целевого узла. Запись
   `running` без подтверждённого результата требует разбора; завершение локального
   SSH-процесса не доказывает прекращение удалённых действий.
3. Сохраните исходные события до очистки spool или удаления стенда. Команда
   `egw clean` не предназначена для экспорта доказательств инцидента.
4. Передайте материалы администратору по утверждённой процедуре. Не восстанавливайте
   файл из карантина и не добавляйте исключения ради прохождения теста.

Оставьте защиту включённой. Сохраняйте неудачные прогоны с исходными лимитами.
Транспортная задержка и блокировка KES могут быть разными неисправностями.

## Что сохранить до первого запуска

Подготовьте отдельное закрытое хранилище на Host за пределами удаляемой VM.
До выполнения подписанного воркера сохраните следующие материалы:

- Точные подписанные байты скрипта с утверждённым SHA-256.
- Исходную ревизию и её SHA-256.
- Публичный сертификат подписи и результат проверки подписи.
- Утверждённую политику воркера с её независимым хешем.
- Версию системного OpenSSH и результат проверки его подписи.
- Сборку Windows и архитектуру процесса.
- Сборку средства защиты с установленными исправлениями.
- Время выпуска баз и состояние компонентов защиты.
- Идентификатор утверждённой политики защиты и её экспорт, если доступен.
- Манифест, связывающий материалы с конкретным прогоном.

Проверьте хеш копии до отправки первого запроса. Антивирус может удалить файл
на стенде, и одного сохранённого хеша для исследования образца будет недостаточно.
Закрытый ключ подписи экспортировать не нужно. Повторная подпись другим
сертификатом создаёт новый образец и не заменяет утраченный оригинал.

Если экспорт политики недоступен, явно зафиксируйте это. Не меняйте парольную
защиту и не включайте дополнительную телеметрию без согласования.

## Локальное сохранение образца и политики

В исходном checkout доступен скрипт
`scripts/qualification/preserve_endpoint_samples.py`. Он сохраняет только
явно указанный `.ps1` и явно указанную `.json`-политику. Хеши должны поступать
из независимой записи об утверждении, а не вычисляться заново по подозрительному
файлу после обнаружения.

Пример предполагает, что закрытый родительский каталог уже подготовлен вне
публичного репозитория, а переменные оболочки содержат утверждённые хеши:

```sh
python3 scripts/qualification/preserve_endpoint_samples.py capture \
  --worker /private/approved/worker.ps1 \
  --worker-sha256 "$APPROVED_WORKER_SHA256" \
  --policy /private/approved/policy.json \
  --policy-sha256 "$APPROVED_POLICY_SHA256" \
  --output /private/endpoint-evidence/attempt001

python3 scripts/qualification/preserve_endpoint_samples.py verify \
  --bundle /private/endpoint-evidence/attempt001 \
  --worker-sha256 "$APPROVED_WORKER_SHA256" \
  --policy-sha256 "$APPROVED_POLICY_SHA256"
```

Скрипт сохраняет байты без изменения переводов строк и проверяет обратное чтение
перед завершением манифеста. Несовпадение хеша останавливает сохранение.
Существующий каталог не перезаписывается. Незавершённая копия после ошибки
остаётся на диске и не проходит проверку; после разбора используйте новый каталог.
Размер каждого входного файла ограничен 16 МиБ. Повторная проверка сверяет копии
с независимыми хешами, поэтому одновременная подмена копии и манифеста не проходит.

На POSIX родительский каталог должен принадлежать текущему пользователю и быть
недоступен остальным. Созданный каталог получает права `0700`, а файлы — `0600`.
На Windows заранее задайте утверждённую закрытую DACL: скрипт её не проверяет.
Права исходных файлов не меняются.

Манифест подтверждает лишь соответствие переданным хешам. Скрипт не проверяет
Authenticode и не устанавливает вердикт KES. Он не собирает ключи и не обращается
к стенду. Политика может содержать закрытые настройки: полученную копию нельзя
публиковать или отправлять в поддержку без отдельного просмотра.

## Разбор и передача материалов

Команды сбора KES приведены в
[английской инструкции](../ENDPOINT-INCIDENT.md#read-only-kes-collection).
Перед использованием сверьте их со справкой установленной версии продукта.
Сохраняйте ошибки самого сбора. Пустой список угроз не заменяет проверку событий
вокруг конкретной транзакции.

В отчёте отделите наблюдения от предположений:

- Сопоставьте хеш в событии с сохранённым образцом.
- Сопоставьте время обнаружения с фазой транзакции.
- Укажите записанное действие средства защиты.
- Не приписывайте событию конкретное внутреннее правило или вызов API без доказательств.
- Перечислите отсутствующие материалы и невыполненные проверки.
- Различайте переподключение существующего RDP-сеанса и полный вход с загрузкой профиля.

Исходный EVTX оставьте в закрытом архиве. Для поддержки сформируйте отдельный
проверенный экспорт без секретов и настроек клиента. Не отправляйте весь spool:
запрос может содержать чувствительную команду, даже если она не выполнилась.
Отправленный отчёт сам по себе не означает, что вендор признал срабатывание ложным.

Для дальнейшей эксплуатации выберите
[явно согласованный маршрут](ROUTING.md). Отказ от воркера на Bastion не
подтверждает совместимость Windows-контроллера с KES. При RDP-only блокировку
нужно разобрать до повторной приёмки под утверждённой политикой.
