# Выбор маршрута по политике ИБ

Флаг `--route` и усиленные проверки транспорта относятся к невыпущенным
изменениям исходного кода. Опубликованный тег `v0.2.0` не изменён.

Маршрут задаётся конфигурацией. Ошибка подключения не переключает транспорт.
Изменение маршрута требует согласования и явной правки конфигурации.

## SSH разрешён

Создайте стартовую конфигурацию без RDP-воркера:

```sh
egw config init --route ssh
egw config check
egw doctor --preflight
```

Используйте [пример SSH-конфигурации](../../config/enclave.ssh.example.yaml).

Основные настройки:

- `bastion.enabled: false` отключает RDP-релей.
- `targets.app01.via: appliance` запускает SSH-клиент на Appliance.
- `ssh_key_path` указывает ключ на исполняющем звене.
- `ssh_known_hosts_path` указывает независимо проверенный файл хост-ключей.

В POSIX Direct исполняющим звеном является локальный Host. Дополнительный
SSH jump host задаётся отдельным узлом с явной цепочкой `via`. Его SSH-служба
должна разрешать утверждённое перенаправление. Воркер на таком узле не нужен.
Для каждого звена задаются собственные ключи. Проверка хост-ключей обязательна.
Парольная аутентификация промежуточного SSH-узла не поддерживается.

Штатные операции сохраняют общий интерфейс:

```sh
egw exec app01 'uname -a'
egw cp ./artifact.bin app01:/tmp/artifact.bin
egw cp app01:/tmp/artifact.bin ./received.bin
egw doctor --probe-targets
```

`config check` показывает выбранные цепочки. Диагностика не требует RDP-пульса.
`heal` не разворачивает воркер и не открывает RDP. `clean` не очищает старый
RDP-spool при выбранном SSH-маршруте.

В режиме Direct Host команда `egw ssh app01` запускает штатный локальный SSH.
Явные SSH jump hosts используют собственные ключи и проверенные хост-ключи.
Пользовательский SSH-конфиг игнорируется на каждом звене. Терминал подключается
напрямую: нажатия клавиш и вывод не записываются как структурированные
транзакции команд. Для такого журнала используйте `egw exec`.

Для маршрута через QGA Appliance интерактивный `egw ssh` ещё недоступен.
Потоковый терминальный мост через QGA не реализован. Команды `stdio-proxy`
и `ssh-config` по-прежнему требуют RDP TCP mux. Экспорт смешанной конфигурации
не подменяет SSH-маршрут через Appliance маршрутом RDP.
Недоступные операции завершаются явной ошибкой до создания локального слушателя. Их список приведён в
[полном руководстве](../ROUTING.md#approved-ssh-route).

## Разрешён только RDP

Укажите `bastion.enabled: true` и `bastion.transport: rdp_vfs`. Целевые узлы
маршрутизируются через `via: bastion`. На Bastion нужен утверждённый процесс:
сам перенаправленный диск не умеет выполнять команды.

Доступны отдельные профили:

- `structured_only` выполняет фиксированные операции через системный OpenSSH.
  Требует подписанного сценария и независимо утверждённой политики целей.
  Поддерживает только Files.
- `legacy` сохраняет прежний воркер с требованиями выбранного режима безопасности.
  Позволяет явно выбрать Stream.

Для строгой политики конечных точек используйте
[руководство нового foreground-профиля](../ENDPOINT-POLICY.md). Переносимые тесты
не подтверждают совместимость с корпоративной версией KES. Локальные проверки подписи и ACL прошли на Windows ARM64 с PowerShell 5.1.
Они не заменяют RDP-приёмку и проверку точной версии KES перед внедрением.

## Общие гарантии

Выбор маршрута не заменяет режим безопасности. Сам по себе SSH не создаёт
гарантию Enterprise-изоляции.

Общими остаются:

- Ролевые политики.
- Журнал транзакций.
- Сквозная проверка файлов по SHA-256.
- Очистка секретов из вывода.
- Запрет автоматического повтора операции с неопределённым исходом.

Возможности выбранного маршрута доступны через `egw capabilities`.
Автоматическое переключение транспорта отключено.
