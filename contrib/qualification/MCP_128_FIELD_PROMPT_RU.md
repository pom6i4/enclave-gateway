# Проверка 128 МиБ через MCP на 0.4.0rc3

> Шаблон для сборщика комплекта. Оператору передавай заполненный
> `FIELD_PROMPT_RU.md` вместе с манифестом и артефактами кандидата.

Обнови Host до точного закрытого кандидата. Выполни один 128 МиБ push через MCP.
После его успеха выполни один pull того же файла. Подтверди целостность и
отсутствие повторного исполнения после перезапуска собственного MCP-сервера.
Новый релиз не публикуй. Прежние артефакты сохрани.

## Подготовка

Используй существующий одобренный Standard operator-маршрут через QGA и RDP.
Сохрани конфигурацию и journal namespace. Сохрани прежнего principal.
Сделай консистентный SQLite online backup. Старую БД поверх новых транзакций
не восстанавливай. Сохрани проверенный rollback wheel v0.3.0.

Установи только целевой wheel без editable. Сравни установленный runtime с ним.
Подтверди 65 совпадающих файлов без расхождений. Если точный RC3 уже установлен,
повторная установка не нужна.

Не меняй агентов или approved pins. Не меняй защиту и её исключения.
Не меняй ACL или сетевую политику. Не запускай supervisor.
Не применяй синтетический ввод. Не завершай чужие процессы или сеансы IDE.
Проверка проводится в собственной согласованной RDP-сессии.

Проверь достаточность свободного места и оставшегося времени lease.
Собственных активных передач перед началом быть не должно.
Сохрани состояние защиты до программы.

Создай закрытый каталог доказательств с правами 0700. Файлам назначь 0600.
Сохраняй исходные аргументы и ответы MCP. Сохраняй Host journal и снимки
durable worker ledger. Все реальные пути и идентификаторы выбирай локально.

Выполни read-only `guest_clock_status()`. Требуй `verified: true` и
`host_clock_stable: true` при полном интервале смещения внутри ±2000 мс.
При невыполнении предусловий остановись. `heal` автоматически не вызывай.

## MCP и бюджеты

Запусти отдельный собственный mutable stdio MCP-сервер из проверенного окружения.
Подтверди initialize:

- `serverInfo.name: enclave-gateway`.
- `serverInfo.version: 0.4.0rc3`.
- `protocolVersion: 2025-03-26`.

Проверь наличие `node_transfer` через tools/list. Подтверди свежую аттестацию
через `enclave_agent`. Требуй `verified: true` и `chunked_copy_slots_v1: true`.
Должно быть подтверждено `operator_copy_max_sec: 45`.

Для основных передач используй:

- `chunked: true`.
- `as_root: false`.
- `timeout_sec: 1800`.
- Клиентский таймаут каждого вызова: 2400 секунд.
- Внешний бюджет наблюдения всей программы: не менее 7200 секунд.

Отключи автоматическую повторную отправку mutating tools/call.
Длительный вызов можно наблюдать асинхронно в одном собственном клиенте.
Повторное чтение состояния фонового задания не должно создавать новый tools/call.

## Один основной push и один pull

Создай на Host новый криптографически случайный файл строго 134217728 байт.
Данные должны быть практически несжимаемыми. Вычисли размер и SHA-256.
Исходный файл во время передачи не меняй.

Выбери новые собственные пути назначения. Они должны изначально отсутствовать.
Не используй пути прежних indeterminate-операций. Для push заранее сохрани
уникальный tx_id. Для pull сохрани другой tx_id. Используй действующий
одобренный alias Linux Target из конфигурации.

1. Отправь ровно один `node_transfer` с `direction: push`.
2. Сохрани ответ и монотонную длительность.
3. Независимым одобренным read-only способом проверь файл Target.
4. Только после успешного push отправь ровно один `node_transfer` с `direction: pull`.
5. Получи файл в новый отсутствующий Host-путь.
6. Проверь размеры и SHA-256 всех трёх копий.

При успехе каждой основной операции требуй:

- Host journal: `completed`.
- `blocks_total: 128`.
- `blocks_verified: 128`.
- `bytes_verified: 134217728`.
- `destination_committed: true`.

При первом отказе основной передачи не запускай следующую основную передачу.
Новый tx_id для повторной попытки не создавай.

## Что именно изменено в RC3

При таймауте периодической read-only аттестации внутри копирования RC3 может
один раз запросить новое подтверждение с новым nonce. Каждая попытка сохраняет
лимит 10 секунд. Все действия остаются внутри прежних 45 секунд текущего шага.
Копирование продолжается только после полной проверки нового ответа.

Сохрани новые поля diagnostics:

- `attestation_attempts`.
- `attestation_retries`.

Нулевое число retries допустимо. Искусственно вызывать timeout не нужно.
Успешно восстановленная read-only проверка не считается второй попыткой передачи.
Проверки identity и пинов не отключай. Лимиты не увеличивай.

## Сверка ledger и отсутствие повторного исполнения

Для основного push ожидаются 128 уникальных `push_part` и один `push_commit`.
Для основного pull ожидаются один `pull_info` и 128 уникальных `pull_part`.
Для каждой успешной операции всего ожидаются 129 copy-записей.
Read-only аттестации в эти числа не включай.

Сопоставь Host `request_publications` с worker ledger по точному operation ID.
Внутренние request ID учитывай отдельно. Проверь отсутствие повторных смещений.
Номер блока вычисляй по `copy_offset / 1048576 + 1`, а не по имени IPC-слота.
Можно использовать `scripts/qualification/copy_ledger.py` из исходного архива.

После успешных основных операций:

1. Сохрани исходные аргументы и результаты.
2. Переименуй собственный исходный файл Host, чтобы прежний путь отсутствовал.
3. Переименуй принятый файл Host, чтобы прежний путь pull отсутствовал.
4. Файл Target пока оставь неизменным.
5. Зафиксируй исходное число copy-записей каждой операции.
6. Закрой только тестовый MCP-сервер через stdin EOF и дождись завершения.
7. Запусти новый сервер с тем же journal namespace и principal.
8. Повтори каждое исходное обращение ровно один раз с прежним tx_id и аргументами.
9. Используй новые JSON-RPC IDs.

Требуй исходные сохранённые результаты и diagnostics. Новых copy-dispatch
должно быть ноль. Новых copy-записей ledger должно быть ноль. Прежние локальные
пути не должны появиться вновь. Файл Target должен остаться неизменным.
Сравнивай тело результата, а не новый JSON-RPC ID.
Нормальное обновление heartbeat не является повторным копированием.
Совпадение SHA-256 без проверки dispatch и ledger не доказывает отсутствие replay.

## При ошибке

Автоматический повтор копирования запрещён. Сначала сохрани read-only состояние
через `enclave_transaction` с `action: get` и исходным tx_id. Сверь journal,
worker ledger и фактическое состояние собственных файлов.

Для indeterminate после сверки допускается ровно одно контролируемое обращение
с тем же tx_id и полностью прежними аргументами. Требуй:

- `transaction_indeterminate`.
- `indeterminate: true`.
- `retryable: false`.
- Исходные diagnostics без изменений.
- Ноль новых copy-dispatch.

Не обходи блокировку новым ID. Не очищай indeterminate-записи.
Не применяй reconcile или maintain для разрешения новой передачи.
Сохрани смещение последнего шага и исход последнего worker-запроса.
Отдельно запиши состояние RDP и воркера. Не объявляй сетевую причину доказанной
по одному коду ошибки. Не вычитай UTC разных узлов без измеренной погрешности.

## Завершение

Сохрани финальный read-only замер часов. Закрой только собственные MCP-серверы
через stdin EOF. Штатно останови только свой тестовый воркер с бюджетом 60 секунд.
Подтверди свежий `stopped` и свободный эксклюзивный lease.
Повтори наблюдение через 10 секунд и проверь отсутствие respawn.
Сравни защиту до и после. Сохрани все неопределённые исходы.
После сверки удали только собственные синтетические файлы.
Глобальную очистку spool или journal не выполняй.
Укажи конечную установленную версию Host и оставшиеся собственные процессы.
