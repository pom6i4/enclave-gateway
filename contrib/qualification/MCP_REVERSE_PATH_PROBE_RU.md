Результат полной приёмки остаётся «ПРОВЕРКА НЕ ЗАВЕРШЕНА».
Без подтверждённого дефекта не меняй код продукта.

## Сначала только сохранённые доказательства

Сохрани закрытую копию исходных доказательств с SHA-256 входных файлов.
Сохрани права 0700 для каталогов и 0600 для файлов.
Скрипты наблюдателя изучай как текст; автоматически не исполняй их.

Для каждой из шести попыток pull сопоставь точный внутренний request ID
с durable worker ledger. Сопоставь внешний operation ID отдельно.
Публично используй только номера попыток.

Зафиксируй последовательность границ:

1. Публикация запроса Host.
2. Получение воркером.
3. Завершение Target OpenSSH.
4. Начало публикации ответа воркером, если оно наблюдалось.
5. Завершение публикации ответа воркером, если оно наблюдалось.
6. Размер ответа, видимый Appliance.
7. Чтение Host через QGA.
8. Истечение исходного лимита шага.
9. События отключения и восстановления RDP.
10. Состояние воркера после ошибки.

Для каждой границы укажи источник наблюдения и часы измерения.
Учти, что воркер записывает completed в ledger до отправки ответа.
Широкая failure_stage `ssh` остаётся выбранной и при финальной публикации.
Сопоставь `exit_code` с наличием `operator_failure_phase`.
Не выдавай completed за подтверждение доступности ответа на Appliance.
Не вычитай UTC разных машин без измеренной погрешности синхронизации.
Не выдавай file timestamp за время первого появления файла.
Не выдавай длительность QGA API за чистую сетевую задержку.
Если наблюдение отсутствует, укажи «не измерено».

Отдельно разбери попытку 3: все 70 worker-запросов завершены.
Поздний ответ относится к блоку 69 при offset 71303168.
В отчёте наблюдателя указаны 55.14 секунды и последующая свежая аттестация.
Проверь, от какой точки отсчитан этот интервал.
Не приписывай этому случаю RDP disconnect без отдельного события.

Для попыток 4–6 проверь события относительно ошибки Host.
Событие после ошибки не доказывает причину уже случившегося таймаута.
Не объявляй Event 1105 доказательством неисправности UDP или VPN.
Эффективные policy limits были нулевыми в сохранённом окне.
Прежнюю гипотезу 25-минутного input-idle timeout не используй как факт.

## Один ограниченный эксперимент при нехватке наблюдений

Новый сетевой эксперимент разрешён только при согласованном доступе к
тестовому окну. При отсутствии доступа заверши офлайн-анализ с пробелами.
Не создавай канал или административные права, которых раньше не было.

Используй собственную согласованную RDP-сессию и прежний Host journal.
Получение свежей аттестации обязательно. Mutable MCP retries отключи.
Сохрани обычный лимит шага 45 секунд. Общий бюджет пробной передачи — 300 секунд.
Клиентский таймаут должен быть больше общего бюджета.

Создай один случайный синтетический файл 8388608 байт на одобренном Target.
Для его подготовки используй только уже разрешённый способ.
Запиши размер и SHA-256. Если разрешённой подготовки нет, не обходи policy.
Выполни один MCP pull с `chunked: true` в новый собственный Host-путь.
Используй новый tx_id только для этой независимой пробной операции.
Не используй прежние пути indeterminate-операций.

Согласованный независимый наблюдатель может читать локальные метаданные
spool на Appliance, если такой доступ уже разрешён. Не держи spool-дескрипторы.
Не добавляй конкурирующий QGA reader ради измерений: он изменит нагрузку.
Не сохраняй содержимое рабочих файлов. Редкая выборка метаданных должна
иметь записанную периодичность. При отсутствии независимого наблюдателя
честно сохрани эту границу как неизмеренную.

На первой ошибке останови программу. Не увеличивай размер и не запускай цикл
повторных попыток. Сохрани Host diagnostics и journal. Сохрани снимок ledger.
Сохрани события RDP в том же окне. Не очищай IPC до сверки доказательств.
Не повторяй indeterminate-запрос ради ещё одного доказательства no-replay:
это уже проверено. Не создавай новый ID для обхода его состояния.

Если 8 МиБ проходят, сообщи только об успешной малой пробе.
Она не закрывает обязательную передачу 128 МиБ и не доказывает устранение сбоя.

## Завершение и отчёт

Штатно закрой только свой MCP-сервер через stdin EOF.
Останови только собственный тестовый воркер с подтверждением stopped.
Подтверди свободный lease и отсутствие respawn после 10 секунд.
Проверь сохранность endpoint protection. Удали только собственные тестовые
файлы после сверки. Indeterminate-записи сохраняй.

Начни отчёт с одного итога для диагностической программы:

- УСПЕХ — граница задержки установлена достаточными наблюдениями.
- НУЖНЫ ДОРАБОТКИ — установлен воспроизводимый дефект продукта.
- ПРОВЕРКА НЕ ЗАВЕРШЕНА — нужная граница остаётся неизмеренной.

Отдельно напиши: «Полная полевая приёмка RC1: ПРОВЕРКА НЕ ЗАВЕРШЕНА».
Укажи подтверждённые факты и отдельно оставшиеся гипотезы.
Предложи минимальную доработку только при установленном дефекте.
Не объявляй сетевое ограничение доказанным по одному коду ошибки.

Публичные обозначения:

- HOST_A.
- APPLIANCE_A.
- BASTION_A.
- TARGET_A.

Не включай адреса или реальные имена. Не включай логины и SID.
Не включай частные пути или session IDs. Не включай private policy hash.
Не включай staging-bundle ID. Не включай конфигурацию и секреты.
Raw traces и `private-inputs.json` остаются только в закрытом каталоге.
