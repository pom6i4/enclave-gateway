# Точечная проверка неопубликованного 0.4.0rc1

Проверь Standard operator-кандидат по закрыто переданному манифесту.
Релиз не публикуй. Тег и артефакты `v0.3.0` сохрани.

Эта полная программа уже выполнялась для исходного RC1; обязательный pull не
завершён. Перед новым запуском используй
[точечную диагностику обратного канала](MCP_REVERSE_PATH_PROBE_RU.md).
Не повторяй шесть неудачных передач без новых наблюдений.

Перед началом установи идентичность из проверенного комплекта:

- Полный commit: `{{CANDIDATE_COMMIT}}`.
- SHA-256 wheel: `{{CANDIDATE_WHEEL_SHA256}}`.
- Версия пакета: `0.4.0rc1`.
- Версия аттестации воркера: `0.3.0`.

Не подставляй изменяемый main вместо commit. Не угадывай hash. Незаполненная
идентичность означает, что проверка не завершена.

## Имеющиеся доказательства

Для третьей неудачной попытки старого `363d8f7` используй приватный снимок worker
ledger. Выполни `scripts/qualification/copy_ledger.py` с точным operation ID.
Сравни `copy_offset` с трассой клиента. Отличай номер блока от номера IPC-слота.
Не объявляй 75 записей равными 75 блокам. Сохрани исходные файлы приватно.
Если их нет, явно оставь расхождение неразрешённым. Новый успешный прогон не
исправляет историческую атрибуцию автоматически.

Сохранённый raw ledger уже позволил сопоставить точный внутренний запрос:
исторический отказ ожидания относится к блоку 74 при offset 76546048.
В этой операции 75 записей включают один `pull_info`.
Прежняя аннотация «блок 123» отозвана как ошибочная.

## Условия сеанса

Сохрани согласованный маршрут и конфигурацию. Используй прежний journal namespace.
Сохрани independently approved pins. Не меняй защиту или её исключения.
Не меняй ACL. Агентов не модифицируй. Чужие процессы и RDP-сеансы не завершай.

До длинной передачи получи эффективные ограничения:

- Предел неактивности ввода.
- Общий предел активного сеанса.
- Правило завершения или отключения при достижении предела.
- Источник эффективной политики и её приоритет.

Используй одобренные средства чтения политик. Самостоятельно настройки не меняй.
Согласуй штатный режим работы на всё окно испытания. Синтетическая активность
указателя не является способом прохождения этой программы. Если одобренных
условий недостаточно, зафиксируй ограничение и не объявляй unattended-приёмку.

## Обновление и MCP

Сохрани проверенный wheel `v0.3.0` для отката. Сделай корректный SQLite backup.
Не восстанавливай старую базу поверх новых транзакций. Установи точный wheel
кандидата в выбранное Host-окружение без editable. Сверь runtime-файлы с wheel.

Выполни `mcp_installed.py` на изолированной конфигурации. Затем запусти отдельный
собственный mutable MCP-сеанс с прежним рабочим журналом. Дождись initialize:

- `serverInfo.name: enclave-gateway`.
- `serverInfo.version: 0.4.0rc1`.
- `protocolVersion: 2025-03-26`.

Отключи автоматические retries mutating-вызовов. Клиентский таймаут должен
превышать общий бюджет операции. Подтверди свежую аттестацию воркера.

## Передача и диагностика

Используй новые случайные синтетические файлы. Выполни один 128 МиБ push через
MCP `node_transfer`. Затем выполни pull того же файла в новый Host-путь.
Используй `chunked: true`. Задай `timeout_sec: 1800`. Для каждой операции выбери
новый tx_id. Не перезаписывай рабочие файлы.

Проверь размер 134217728 байт и SHA-256 всех трёх копий. Сохрани монотонные
длительности. Сохрани `diagnostics` из результатов либо ошибок. Сохрани journal.
Сопоставь его с worker ledger.

Проверь структурные наблюдения:

- `blocks_total: 128` для данного непустого размера.
- При успехе `blocks_verified: 128`.
- При успехе `bytes_verified: 134217728`.
- При успехе `destination_committed: true`.
- При отказе номер части согласован с точным смещением.
- Число публикаций сопоставимо с copy-запросами ledger.

У pull есть отдельный `pull_info`. У push есть отдельный `push_commit`.
Не смешивай число запросов с числом блоков. Измерения времени вложенные;
не суммируй их как непересекающиеся этапы.

При таймауте не повторяй передачу автоматически. Сначала сверяй журнал и
фактическое состояние. Лимит шага самостоятельно не увеличивай.

## Нет повторного исполнения

После успеха сохрани результат. Переименуй собственные локальные тестовые файлы,
чтобы прежние пути отсутствовали. Закрой только тестовый MCP-сервер через stdin
EOF. Запусти его снова с тем же journal и principal. Повтори исходные запросы
с теми же tx_id и аргументами. JSON-RPC IDs должны быть новыми.

Требуй прежние сохранённые результаты и diagnostics. Новых copy-dispatch быть
не должно. Прежний путь скачивания не должен появиться вновь.

Если возникла неопределённая операция, после сверки её исхода проверь один
неизменный запрос с тем же ID. Требуй отказ от нового исполнения с сохранёнными
observations. Не создавай новый ID для обхода indeterminate. Не вызывай сетевой
сбой специально: локальная регрессия позднего ответа записана отдельно.

## Завершение и отчёт

Штатно останови только собственный тестовый воркер. Требуй свежий stopped.
Подтверди свободный lease. Проверь отсутствие самозапуска после 10 секунд.
Сохрани неопределённые операции. После сверки удали только свои тестовые файлы.
Сравни endpoint protection до и после. Укажи конечную версию Host.

Начни отчёт с одного итога:

- УСПЕХ.
- НУЖНЫ ДОРАБОТКИ.
- ПРОВЕРКА НЕ ЗАВЕРШЕНА.

Отдельно укажи историческую сверку. Отдельно укажи условия RDP-сеанса.
Приведи обе передачи с количеством попыток. Приведи наблюдения диагностики
и доказательства отсутствия replay. Подтверждённая регрессия означает НУЖНЫ
ДОРАБОТКИ. Недостаток обязательного доступа или незавершённая передача означает
ПРОВЕРКА НЕ ЗАВЕРШЕНА. Один цикл не доказывает бессрочную надёжность.

Публично используй HOST_A / APPLIANCE_A / BASTION_A / TARGET_A. Исключи адреса.
Исключи логины и SID. Исключи частные пути и сеансовые IDs. Исключи конфигурацию
и секреты. Исключи hash приватной policy. Исключи staging-bundle IDs.
Raw traces и `private-inputs.json` остаются приватными.
