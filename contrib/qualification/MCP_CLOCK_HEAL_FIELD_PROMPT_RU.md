# Короткая проверка часов после исправления QGA

> Шаблон для сборщика комплекта. Не передавай этот файл оператору напрямую.
> Для проверки используй заполненный `FIELD_PROMPT_RU.md` из закрытого комплекта
> вместе с его `candidate-manifest.json` и `SHA256SUMS`.

Проверь исправление синхронизации часов в согласованном Standard operator-контуре.
Это проверка часов, а не приёмка передачи 128 МиБ. Релиз не публикуй.
Сохрани тег и исходные артефакты `v0.3.0`. Сохрани исходный комплект RC1.

## Точная идентичность

Получив новый закрытый комплект, заполни идентичность из его манифеста:

- Commit: `{{CLOCK_FIX_COMMIT}}`.
- Версия пакета: `{{CLOCK_FIX_VERSION}}`.
- SHA-256 wheel: `{{CLOCK_FIX_WHEEL_SHA256}}`.
- Версия аттестации воркера: `0.3.0`.
- SHA-256 неизменного адаптера:
  `9e74e6d3574be53610bdce46c4d8182036630fbf4455183219c97572bd25f046`.

Не подставляй изменяемый main. Не угадывай hash.
Исходный RC1 от `a8d9cf0fa60219220e5363d33bd2423ec90e2818`
не содержит нового исправления. Одинаковая строка версии не доказывает
идентичность wheel. Без заполненного нового манифеста проверка не завершена.

## Подготовка

Работай в отдельном собственном тестовом MCP-сеансе. Чужие процессы не завершай.
Сохрани существующий Host journal namespace и его корректный SQLite backup.
Сохрани проверенный rollback wheel. Не восстанавливай старую БД поверх новых
транзакций. Останови собственные активные операции до обновления Host.
Установи точный новый wheel без editable. Сверь runtime с этим wheel.
Проверь новый stdio MCP initialize с ожидаемой версией.

Сохрани approved pins и прежний маршрут. Агентов не модифицируй.
Не добавляй исключения защиты. Не запускай supervisor или синтетический ввод.
Не меняй время Bastion — он должен использовать одобренный доменный источник.

Учти: полный `heal` также применяет настройки сети на управляемом Appliance.
До его вызова сравни текущие значения с одобренными настройками.
Если вызов изменит сетевую политику за пределами согласованного окна,
не выполняй его и сообщи об этом ограничении. Подготовленный новый код не
является разрешением самостоятельно менять защиту или сетевую политику.

## Измерения

Для QGA используй read-only `guest-get-time` через новый метод
`guest_clock_status()`. Не измеряй часы посредством запуска PowerShell.
Ожидание lock и синхронизации потока не включай в измерительное окно.
Сохраняй структурный результат метода без адресов и частных путей.

Последовательность:

1. Сними один исходный замер часов Appliance относительно Host.
2. Запиши свежую аттестацию собственного воркера, если он уже работает.
3. Выполни ровно один штатный `heal` без restaging и обновления credentials.
4. Сохрани exit code и строку `APPLIANCE_CLOCK_CHECK`.
5. Сними отдельный read-only замер сразу после завершения `heal`.
6. Сними ещё один read-only замер через 60 секунд.
7. Сними финальный read-only замер через 300 секунд после `heal`.

Для каждого замера укажи:

- `offset_ms` со знаком Appliance минус Host.
- `offset_lower_ms`.
- `offset_upper_ms`.
- `uncertainty_ms`.
- `rtt_ms`.
- `tolerance_ms`.
- `host_clock_stable`.
- `verified`.

Порог в новом коде — весь интервал смещения внутри ±2000 мс.
Слишком широкое окно не является успешной синхронизацией даже при среднем
смещении около нуля. Скачок Host wall clock делает наблюдение непригодным.
Подтверждение `guest-set-time` само по себе не заменяет итогового измерения.

При ненулевом exit code не повторяй `heal` автоматически.
Сохрани исходный результат и журнал. Не объявляй предыдущую установку времени
неисполненной только потому, что read-only подтверждение недоступно.
При сбое наблюдения останови программу без нового mutating-вызова.

Для работающего operator-воркера проверь сохранность его identity после `heal`.
Проверь свежую аттестацию и непрерывность собственной RDP-сессии.
Публично сообщи только результат сравнения identity, без самих идентификаторов.

Не выполняй передачу 128 МиБ в этой программе. Не повторяй неопределённые
операции копирования. Этот тест не устанавливает причину задержки pull.

## Завершение и отчёт

Закрой только свой тестовый MCP-сервер через stdin EOF.
Если для программы был запущен собственный тестовый воркер, штатно останови его.
Подтверди stopped и свободный lease. Повтори наблюдение через 10 секунд,
чтобы проверить отсутствие respawn. Ранее существовавший чужой воркер не трогай.
Сравни состояние защиты до и после. Укажи конечную установленную версию Host.
Сохрани journal и все исходные измерения в закрытом каталоге.

Начни отчёт с одного итога:

- УСПЕХ — новый пакет проверен, `heal` успешен и последующие замеры проходят порог.
- НУЖНЫ ДОРАБОТКИ — воспроизводимо подтверждён дефект исправленного кода.
- ПРОВЕРКА НЕ ЗАВЕРШЕНА — нет обязательного доступа или достоверного замера.

Приведи последовательность измерений с погрешностью.
Отдельно сообщи: «Полная приёмка передачи 128 МиБ: ПРОВЕРКА НЕ ЗАВЕРШЕНА».
Не объявляй исправление часов исправлением обратного транспортного канала.

Публичные обозначения:

- HOST_A.
- APPLIANCE_A.
- BASTION_A.
- TARGET_A.

Исключи реальные имена и адреса. Исключи логины и SID.
Исключи private paths и session IDs. Исключи private policy hash.
Исключи staging-bundle IDs. Исключи конфигурацию и секреты.
Raw traces остаются исключительно в закрытом каталоге.
